# 0.8 — Featured/Tips transport compatibility

Target: Douyin 40.6.0, build 406019. Preserve original IPA, candidates, app data and both tabs.

1. Match device error to native construction. The 0.7 report has 23 app-wide serializer errors `com.aweme.network.error/-11001` with NSData input; eight DC callbacks have this domain/code. These are different counters, not 23 unique Featured/Tips requests. The displayed conversion message matches the native serializer. The exact payload and HTTP metadata are still unknown. App/-4 is not a confirmed authentication error.
2. Trace fetch, refresh and pagination. Native `AWEDCFeedListDataManager` chooses either its chunk controller or normal `dataController` based on `shouldRequestWithChunk`. Initial and load-more branches were disassembled; refresh is checked separately. The normal default wrapper already implements all three request types. Chunk framing is proprietary; do not guess a decoder or concatenate partial records.
3. Implement reversible **Feed compatibility**. Default ON. Call the original decision once; if it requests chunks and the native standard wrapper plus all three method ABIs are compatible, return NO to choose the native normal path. Missing/incompatible controllers retain original behavior. OFF restores original decision. Do not issue an extra request, substitute content, clear errors, change authentication or alter cursor/hasMore.
4. Expand privacy-preserving error classification. Read TTHttpResponse HTTP status/MIME through checked ABIs. Report fixed size/prefix categories. Strict Foundation parsing is diagnostic only: at most 32 attempts per process, each no more than 2 MiB. Keep original model, error pointer, transport error and server decisions. No response bytes, URLs, headers, cookies or usernames are exported.
5. Keep failure semantics honest. Native data state 8 triggers error page 10 even when the view briefly contains placeholder data. Do not replace it with a success state or fake fresh videos. Fix the request path before changing presentation. Existing stored/placeholder videos do not prove successful pagination.
6. Validate packaging, Foundation forwarding/ABI/controller availability/OFF/native errors/pagination preservation/input bounds/privacy, arm64 compilation and UIKit fixtures. Review the actual settings screenshot with the new option. Independently compare packaged IPA with original/audit.
7. Device acceptance: open Featured and Tips separately, refresh once, scroll through multiple pages, check new videos and absence of conversion error/flicker, then copy diagnostics. Confirm `DC transport standard selected` is present, not merely Installed. If errors remain, HTTP/content/prefix classifications distinguish rejected requests, compressed/non-JSON payloads or native model errors. Do not claim full resolution until tested on physical iPhone.

Rollback: turn Feed compatibility OFF, close/reopen app. Other options unchanged. No persistent data migration, tab removal, third-party streams or binary code replacement.
